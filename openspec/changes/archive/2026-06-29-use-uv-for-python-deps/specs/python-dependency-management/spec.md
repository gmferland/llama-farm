## ADDED Requirements

### Requirement: Project declared as PEP 621 package
The agent coding service SHALL declare its metadata and runtime dependencies in `agent/coding/pyproject.toml` using the `[project]` table (PEP 621). The `requires-python` field SHALL be set. There SHALL be no `[build-system]` table.

#### Scenario: pyproject.toml exists with required fields
- **WHEN** a developer opens `agent/coding/pyproject.toml`
- **THEN** the file contains a `[project]` table with `name`, `version`, `requires-python`, and `dependencies` fields

#### Scenario: All current dependencies are declared
- **WHEN** `uv sync` is run in `agent/coding/`
- **THEN** all packages previously in `requirements.txt` are installed without error

### Requirement: Dependency lock file committed to repository
The project SHALL include a committed `agent/coding/uv.lock` file generated by `uv lock`. This file SHALL be regenerated and committed whenever `pyproject.toml` dependencies change.

#### Scenario: Lock file is present in source control
- **WHEN** the repository is cloned fresh
- **THEN** `agent/coding/uv.lock` exists and `uv sync --frozen` succeeds without network access to resolve versions

#### Scenario: Lock file drift is caught at build time
- **WHEN** `pyproject.toml` dependencies are changed without regenerating `uv.lock`
- **THEN** running `uv sync --frozen` exits with a non-zero status and an error indicating the lock file is out of date

### Requirement: Docker image built using uv
The `agent/coding/Dockerfile` SHALL install `uv` and use `uv sync --frozen --no-dev` to install dependencies. The application SHALL be launched via `uv run`.

#### Scenario: Docker build succeeds with lock file present
- **WHEN** `docker build` is run for `agent/coding/`
- **THEN** the build completes successfully and the resulting image runs `uvicorn` on port 8000

#### Scenario: Docker layer cache is effective for dependency installs
- **WHEN** application source files change but `pyproject.toml` and `uv.lock` do not
- **THEN** the `uv sync` Docker layer is served from cache and the build does not reinstall dependencies

### Requirement: Local development using uv venv
A developer SHALL be able to create a local virtual environment and install dependencies by running `uv sync` in `agent/coding/`. The virtual environment SHALL be created at `agent/coding/.venv/`.

#### Scenario: First-time local setup
- **WHEN** a developer runs `uv sync` in `agent/coding/` on a machine with `uv` installed
- **THEN** a `.venv/` directory is created and all project dependencies are installed into it

#### Scenario: Running the service locally
- **WHEN** a developer runs `uv run uvicorn app:app --host 0.0.0.0 --port 8000` in `agent/coding/`
- **THEN** the application starts successfully using the managed virtual environment
